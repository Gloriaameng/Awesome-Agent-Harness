Agent Harness for Large Language Model Agents: A Survey

Qianyu Meng1,3*, Yanan Wang2,3*, Liyi Chen3†, Yihang Li3, Wei Wu3,4, Wenyuan Jiang3,4, Qimeng Wang3, Chengqiang Lu3, Yan Gao3, Yi Wu3, Yao Hu3

论文 PDFDOI代码与资源索引数据集BibTeX

要点：智能体行为是模型—harness—环境这一完整配置的属性，而非模型单独的属性。本文界定 agent harness，将其分解为六类运行时功能（ETCSLV），依据第一方证据对 34 个系统进行编码比较，并梳理 harness 效应的评测方法。

概述

大语言模型智能体并不直接作用于环境，而是经由一层运行时完成上下文组装、模型调用、工具路由、状态持久化、策略执行与轨迹记录。本文将这一运行时称为 agent harness，并论证它是智能体可观测行为的重要共同决定因素，却常在研究报告中缺乏充分说明。因此，本文以模型—harness—环境配置为分析单元；该配置同时规定权限、资源预算与评测器。

本文将 harness 分解为六类反复出现的职责，即 H = (E, T, C, S, L, V)：执行循环、工具注册表、上下文管理器、状态存储、生命周期钩子与评测接口。基于这一框架，本文依据第一方文档与源代码对 34 个系统进行编码，每项评分均记录来源、版本、访问日期与置信度，并对 Claude Code、Codex、DeepSeek Harness 与 OpenClaw 展开深入分析。在此基础上，本文将 harness 评测研究归纳为六个方向，并区分四种 harness 适应形式：从单次运行内的反思，到与模型权重的协同演化。

什么是 Agent Harness？

Agent harness 是位于语言模型与环境之间的运行时软件，负责驱动执行循环、组装上下文、提供并管控工具、持久化状态，并记录评测所需的证据。

示例：修复一个未通过的测试

模型提出代码修改；harness 决定模型可见的文件与指令，提供编辑与命令行工具，核查授权，运行测试并返回结果。若运行中断，harness 须恢复足够的状态，才能在不重复已完成动作的前提下继续执行。一次失败可能源于模型决策、上下文缺失、工具不可用或恢复策略，仅凭最终输出无法加以区分。

Harness 与框架、脚手架和 MCP 的区别

Harness
经过配置的运行时，承载智能体从多轮模型调用、动作执行到状态转移直至任务终止的全过程。
框架 / SDK
用于构建运行时的可复用组件。实际部署的 harness 通常将其与应用层的策略和服务组合使用。
脚手架（scaffold）
组织模型行为的提示词与工作流结构。该术语与 harness 存在交叠；本文进一步明确了其中的执行与治理职责。
MCP
连接客户端与工具、资源提供方的协议。相关能力如何进入执行循环并受权限策略约束，仍由 harness 决定。

ETCSLV：Agent Harness 的六类运行时功能

ETCSLV 概括了公开 harness 架构中反复出现的六类职责，用于定位各项职责的实现位置，而非衡量系统成熟度。

E 执行循环
编排模型调用与动作执行，判定终止条件，并处理重试、任务委派与故障恢复。
T 工具注册表
定义模型可调用的动作及其参数模式、路由、结果处理与执行契约。
C 上下文管理器
为每次模型调用筛选并转换指令、历史记录、观察结果、检索内容与摘要。
S 状态存储
跨轮次与进程重启持久化对话、工作区、检查点、记忆与待执行操作。
L 生命周期钩子
在执行步骤前后施加权限、审批、凭据、沙箱与审计控制。
V 评测接口
向评测器提供执行轨迹、中间状态、结果、成本与配置元数据。

历史演进

当代 harness 汇聚了三条脉络中的运行时思想：软件测试 harness、交互式环境与大语言模型智能体架构。

34 个 Agent Harness 系统的比较

本文依据第一方文档与源代码，按 ETCSLV 六类功能对 34 个系统进行编码。每项评分均记录来源、版本或提交、访问日期与置信度。数据快照日期：2026 年 10 月 12 日。

主要发现

  • 34 / 34E

    34 个系统均有执行循环的文档记录；这一结果由收录标准所决定。

  • 14 · 18 · 2V

    评测接口是区分度最高的功能：14 个系统评为完整，18 个为部分，2 个尚未核实。

  • 3 ≠ 1S · V

    对话记录、可恢复会话与可复用的评测接口服务于不同目的，因此分别评分。

四个重点系统

  • Claude Code

    产品层

    将代码仓库检索、编辑、命令执行与子智能体委派整合为统一的编程工作流。该案例说明上下文选择与动作审批如何塑造从任务目标到通过测试的代码修改这一路径。

  • Codex

    运行时层

    通过执行循环衔接模型事件与工具事件，并提供持久化的执行记录（rollout）、审批与沙箱控制。该案例聚焦于跨客户端界面的可恢复状态。

  • DeepSeek Harness

    插件层

    通过插件、配置方案与补丁暴露运行时组件。该案例关注组件边界以及受控的运行时修改。

  • OpenClaw

    网关层

    通过网关协调通信渠道、持久会话与定时任务。该案例将分析延伸至跨交互持续存在的身份、状态与权限。

四个系统将同一功能置于不同层级：产品、运行时、插件或网关。因此，仅凭系统名称无法确定产生某一结果的具体配置。

Agent Harness 的评测

本文将评测文献归纳为六个方向。各方向涵盖基准、方法与平台，分别回应不同的研究问题。

三类评测问题

  • 配置比较. 在声明的实验条件下，哪一完整配置表现更优？
  • 组件研究. 在其余条件保持不变时，改变单一机制会带来何种变化？
  • 轨迹审计. 权限、状态转移、工具结果与完成声明是否与环境中实际发生的情况相符？

报告 harness 实验结果时，应说明模型与运行时版本、任务环境、工具与审批设置、预算及执行记录，并同时报告成本、恢复行为与策略合规情况。

六个评测方向

Harness 效应

在固定模型与任务的条件下，比较不同运行时配置，或隔离单个组件的作用。

  • Harness-Bench
  • Beyond the Model
  • LongHarness Bench
  • Harness the Memory
  • WildClawBench

Harness 演化与持续评测

在工具、技能、会话或运行时组件发生变化时，测量系统的适应与保持能力。另有五项相关工作见下表。

  • SCLATE
  • VeRO
  • AgentSWE

生命周期、安全与审计

考察权限控制、攻击影响与恢复能力，以及执行记录能否支持独立核查。

  • HarnessRisk
  • HarnessSecurity-Bench
  • Hearsay
  • SandboxEscapeBench
  • HarnessAudit-Bench

长时循环与恢复

检验持续推进能力、累积的待履行事项，以及部分失败后的恢复能力。

  • LoopsBench
  • Long-Horizon-Terminal-Bench
  • SWE-Chain
  • ChainSWE
  • Hell or High Water

协议与工具基础

分别评测协议一致性、工具选择、工具执行与经核验的实际效果。

  • DynamicMCPBench
  • MCP-Bench
  • MCP-AgentBench
  • MCPAgentBench

评测基础设施

提供可重复的运行、可替换的智能体与环境、执行轨迹以及评分器。

  • AgentCompass
  • Harbor
  • HAL

OSWorld、WebArena、GAIA 与 SWE-bench 等任务环境衡量的是完整配置系统的表现；若要隔离 harness 效应，还需引入额外的控制条件。

Harness 演化：改变的对象

工作改变对象研究问题
SkillOpt可复用的技能文本如何利用 rollout 反馈指导对技能的持久修改？
Meta-Harness可执行的 harness 代码如何利用执行轨迹与任务得分指导对运行时实现的搜索？
AutoHarness任务特定的 harness 与策略代码如何利用环境反馈生成用于校验动作的代码？
EvoHarnessBench工具、技能与智能体配置如何跨阶段测量适应与保持能力？
TaoLive模型权重与运行时组件模型训练如何与持续变化的 harness 相互作用？

开放问题

  • 配置效应. 在条件匹配的实验中，测量模型、harness、环境与策略之间的交互作用。
  • 状态连续性. 检验哪些状态能够在上下文压缩、重启、冲突、权限撤销与删除之后得以保留。
  • 独立评测. 将执行轨迹与环境中的实际结果，以及智能体无法操控的外部记录相互对应。
  • 有边界的演化. 在留出任务、分布外任务、回归任务与安全任务上评测带版本标识的 harness 修改。
